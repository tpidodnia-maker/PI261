# ДЗ: Линейный поиск в C#

## Задание 1 — Поиск элемента

Метод `Find(numbers, target)` идёт по массиву с начала и на первом совпадении делает `return i`.
Если цикл закончился и ничего не нашли — `return -1`.

Проверяются граничные случаи:
- элемент в начале,
- элемент в конце,
- элемента нет,
- пустой массив.

**Запуск:**
```
cd Задание1
dotnet run
```

## Задание 2 — Замеры времени

Меряем `Stopwatch`, повторяем 1000 раз, берём среднее.

Три случая:
- **лучший** — искомый первый элемент,
- **средний** — искомый в середине,
- **худший** — элемента нет (проходим весь массив).

**Запуск:**
```
cd Задание2
dotnet run
```

> Полный прогон на 10 000 000 элементов занимает какое-то время (миллиарды сравнений), это нормально.

## Таблица результатов

Мои замеры на этом компьютере (Debug, среднее по 1000 запускам):

| Размер массива, N | Лучший, мс | Средний, мс | Худший, мс |
|---|---|---|---|
| 1 000 | 0,0001 | 0,0011 | 0,0022 |
| 10 000 | 0,0000 | 0,0111 | 0,0219 |
| 100 000 | 0,0000 | 0,1116 | 0,2233 |
| 1 000 000 | 0,0000 | 1,1929 | 2,3022 |
| 10 000 000 | 0,0000 | 11,4581 | 23,7597 |

(в лучшем случае время почти нулевое — поиск заканчивается на первом же элементе,
поэтому на фоне 1000 запусков округляется до 0,0000)

## Вывод

Время растёт линейно вместе с размером массива N. При увеличении N в 10 раз среднее и худшее время тоже растут примерно в 10 раз — это подтверждает сложность O(N).

В лучшем случае (искомый элемент первый) время от N почти не зависит, потому что поиск заканчивается сразу на первом элементе.
